# ROS 2 Dynamic Path Planning
**A* vs D* Lite Global Planners for Nav2 - Replanning in Dynamic Environments**

[![ROS 2 Humble](https://img.shields.io/badge/ROS_2-Humble-brightgreen)](https://docs.ros.org/en/humble/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![C++20](https://img.shields.io/badge/C++-20-blue)](https://en.cppreference.com/w/cpp/20)

A* and D* Lite implemented as Nav2 global planner plugins, with a benchmark
comparing how each handles a map that changes mid-route.

> **Status (July 2026): benchmark results retracted, rework in progress.**
>
> I reviewed this repository and found that the previously published benchmark
> (the "22.4% faster, 200 trials" claim) did not hold up: the committed results
> file was not generated by the benchmark code, the D* Lite implementation
> cleared its search state between replans (so it was not actually planning
> incrementally), and the benchmark timed the two planners under different
> conditions. Those results and figures have been removed.
>
> The rework, in progress on this repository, is:
> 1. a correct D* Lite (backward search, persistent `g`/`rhs` state, proper
>    `km` accumulation) per Koenig & Likhachev,
> 2. unit tests validating path optimality against Dijkstra ground truth and
>    verifying that incremental replans match from-scratch results,
> 3. a fair benchmark where both planners face identical path-blocking
>    obstacle changes and only the replanning work is timed,
> 4. results regenerated from real runs and committed together with the exact
>    code and seed that produced them, verified in CI.

## The planning problem

When the map changes mid-route - someone steps into the corridor - A* discards
its previous search and replans from scratch. D* Lite repairs the existing
solution incrementally, reusing everything still valid. In theory this makes
D* Lite substantially cheaper per replan in dynamic indoor spaces (warehouses,
hospitals, offices). This repository exists to implement both properly and
measure that difference honestly.

The illustrative sketches below show the scenario on this repository's
occupancy map (50 m x 40 m indoor office, 0.05 m resolution). They are
diagrams, not captured algorithm output; real run figures will replace them
when the rebuilt benchmark lands.

## Quick Start (ROS 2 Humble)

```bash
mkdir -p ros2_ws/src && cd ros2_ws/src
git clone https://github.com/munawarkazmi/ros2-dynamic-path-planning.git
cd ..
colcon build --packages-select ros2_dynamic_path_planning
source install/setup.bash
```

1. Demo with D* Lite (RViz auto-opens)
   ```bash
   ros2 launch ros2_dynamic_path_planning dstar_launch.py rviz:=true
   ```

2. Demo with classic A*
   ```bash
   ros2 launch ros2_dynamic_path_planning astar_launch.py rviz:=true
   ```

3. Benchmark (methodology being rebuilt - see Status above)
   ```bash
   ros2 launch ros2_dynamic_path_planning benchmark_launch.py trials:=200 seed:=42
   ```

## Features

- Modern C++20 implementation
- Nav2 global planner plugins (pluginlib)
- Dynamic obstacles via MarkerArray
- Single-parameter planner switching
- Seeded benchmark node with CSV output (methodology under rework)
- Gazebo world with 8 walking actors (in `worlds/`)
